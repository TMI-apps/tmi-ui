# design-sync notes — @tmi-packages/ui

## Config decisions

- **CSS-in-JS, no static stylesheet** (`[CSS_RUNTIME]`, expected): the DS styles everything via MUI/Emotion at runtime. `cfg.cssEntry` is intentionally unset.
- **`cfg.provider`** (`AppProviders`, in `.design-sync/provider/AppProviders.tsx`, wired via `extraEntries`): several components (the whole `DataTable`/`TMITable` family, `DetailPanelHeroHeader`, `TMITableWorkspace`, etc.) read `theme.detailPanelHero` / `theme.tmiTableWorkspace` / `theme.tmiPrimaryContained`, which only exist after running the package's own `createTmiTableTheme(base)` factory. The provider wraps every preview in `ThemeProvider` with that theme, plus `PortaledOverlayStackProvider` (needed for popper/portal z-index stacking used by the AutocompleteSelect group and table overlays).
- **`cfg.overrides.VideoEmbedModal`**: `{"cardMode": "single", "primaryStory": "YouTube"}`. It's a MUI `Dialog` (portal) — both authored stories (YouTube, Vimeo) render identically inside the grid cell and escape the card bounds when open. Single-card mode is the documented fix for overlay components.

## Known render warns (triaged, not chased)

- **`VideoEmbedModal` (YouTube, Vimeo stories)**: the embedded iframe shows the provider's own "video unavailable" / "rights issue" placard in captured screenshots. This is real third-party content — headless Playwright has no authenticated/consented network context for YouTube/Vimeo embeds — not a defect in the modal composition. The dialog chrome (title, close button, 16:9 frame, responsive sizing) is what's actually being verified and renders correctly. Graded `good`.
- **`OptimisticTableFeedbackProvider` (`RollbackToastVisible`, `WarningToastVisible` stories)**: the provider's own fixed-position `Snackbar`+`Alert` renders cropped/misplaced in the multi-cell contact sheet (portal escapes the grid cell, same class of issue as `VideoEmbedModal`). Fixed with `cfg.overrides.OptimisticTableFeedbackProvider: {"cardMode": "single"}`. Verified correct in isolation via a local static serve before the override was added. Graded `good`.
- **`TableRowActionButton` (`[RENDER_THIN]` "mounts have no text and paint nothing")**: false positive from the text-based heuristic — these are icon-only buttons (delete/link icons, no label) by design. Screenshot confirms all 3 variants (AsLink, Default, Disabled) render correctly with distinct icons/opacity. No fix needed.
- **`MetadataFiltersBar`, `RowStyleMultiSelect`, `DatabaseViewer` (`[GRID_OVERFLOW]`)**: these are full-width bar/table components that don't fit a multi-column grid cell. Fixed with `cfg.overrides.<Name>: {"cardMode": "column"}`.

- **`AirtableAttachmentThumbnailCell` (`WithAttachment`) / `TableRowThumbnailShell` (`Default`)**: the "loaded image" story renders the same empty-placeholder icon as the "no image" stories instead of the actual thumbnail. Root cause: `TableRowThumbnailShell`'s `<img>` uses native `loading="lazy"` inside an MUI `Fade` that starts `visibility:hidden`; `package-capture.mjs`'s isolated per-story (`?story=`) page load doesn't give the image enough time/trigger conditions to fire `onLoad` before the screenshot — confirmed via live DOM diagnosis (a self-contained `data:` URI reproduces it identically to a remote URL, ruling out network flakiness; forcing `img.loading='eager'` on the live element loads it instantly). Not fixable from the authored `.tsx` (`loading` is hardcoded in the shipped component). Not a real product defect — `package-validate.mjs`'s combined-page render check does not flag either component at all. Graded `needs-work` on just that one cell each rather than forced to `good`. A future fix belongs in `package-capture.mjs`'s per-story wait strategy (e.g. `page.waitForFunction(() => [...document.images].every(img => img.complete))` before the screenshot) — a first attempt at that during this sync caused a worse regression (see git history / this note) and was reverted; a real fix needs more care than a quick patch.

## Gotchas for the next sync

- **React Router `Link` stories can't render statically.** `ThumbnailPill`'s `to` prop renders a `react-router-dom` `Link`. The per-component preview `.tsx` is compiled as its own small esbuild bundle, which pulls in a *second, separate* copy of `react-router-dom` from `node_modules` — different from the copy inlined into the main `_ds_bundle.js` for `ThumbnailPillParts.tsx`. The two copies' React Context objects don't match, so even wrapping the story in `<MemoryRouter>` throws (`Cannot destructure property 'basename' of 'React.useContext(...)' as it is null`). Worked around by authoring the `AppBarVariant` story with `onClick` instead of `to` — same visual variant (`variant="appBar"`), no router dependency. If a future preview genuinely needs to demonstrate router-linked behavior, this dual-instance issue will need a real fix (e.g. forcing the preview bundle to treat `react-router-dom` as external and resolve from the same inlined instance), not just a story-level workaround.

## Content conventions

- `AutocompleteSelectField`, `MetadataFiltersBar`, `PrimaryContainedAutocompleteBar`, `RowStyleMultiSelect` previews use realistic Dutch lesmateriaal/curriculum-domain content (vakken, groepen, leerdoelen) rather than placeholder "Alpha/Beta/Gamma" text — keep this convention for any future components in this domain.
- `AirtableAttachmentThumbnailCell`/`TableRowThumbnailShell` previews use an inline SVG `data:` URI constant rather than a remote `picsum.photos` URL, specifically so "loaded" stories don't depend on an external fetch — a strict improvement even though it didn't fully resolve the lazy-load timing gap above.
- `RowStyleMultiSelect`'s autocomplete-open (expanded) state has no prop to force it externally and requires a real click — intentionally omitted as non-statically-renderable, same class as hover/drag states.
- `PersistentStepperStepItem` (a leaf with no sensible standalone defaults) is composed per the leaf-inside-parent rule: each story builds the exact `StepItem`/`ChecklistSizing`/`gradientBullet`/`hoverBg` shape `PersistentStepperList` itself constructs, wrapped in the same `<Box component="ul">` — not a simplified reimplementation.

## Re-sync risks

- `theme.detailPanelHero` etc. are filled by calling `createTmiTableTheme(createTheme({palette:{mode:"light"}}))` inside `AppProviders.tsx` — always **light mode**. If TMI apps that actually consume this DS render it dark-first (worth checking against the separate TMI brand-tokens bundle), previews here will look different from production. Revisit if that turns out to matter.
- `AppProviders.tsx` imports several `lesmateriaal-import/**` internal source files by *relative path* (not the package's public `@tmi-packages/ui` export surface), because self-importing the package from inside its own repo doesn't resolve. If those internal files move, the provider breaks silently until the next build.
- Playwright/Chromium was freshly installed for this sync (`C:\Users\Lenovo\AppData\Local\ms-playwright`) — wasn't present before. Future re-syncs on a different machine will need the same install step.
